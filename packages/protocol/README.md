# @sonasub/protocol

**English** | [简体中文](README.zh-CN.md)

Home of the cross-module communication contracts. It currently defines only the loopback WebSocket protocol between the desktop Rust backend and the Node.js engine; audio, subtitle, translation and extension-capture messages are not part of it.

## Current Contract

- `@sonasub/protocol/engine` exports the protocol version, the startup handshake marker, the runtime information types and the boundary parsing functions.
- The engine writes one JSON line prefixed with `SONASUB_HANDSHAKE` to stdout, carrying the protocol version, the actual listening port and the process ID; regular logs must not use that prefix.
- The first WebSocket message is the random credential generated by Rust. Control requests are rejected until authentication completes, and the credential never reaches frontend state or logs.
- The only control requests are `engine.info` and `engine.shutdown`; responses carry the same `id` and distinguish a successful result from an error.
- Runtime information comes from the engine process: engine version, Node.js version, PID and ISO start time.

Rust-side serialization and validation live in `apps/desktop/src-tauri/src/protocol.rs` and stay aligned with these fields and versions. When changing the protocol, update both sides and their tests together, and never import another app's internal source.

Module boundaries are in [docs/architecture.md](../../docs/architecture.md).
